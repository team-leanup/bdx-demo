## 7차 — 고객 등록 후 삭제 기능 (클라이언트 피드백 · 지승호 대표)

> 카톡 요청(파일럿샵 현장): "고객 등록 이후에 삭제 가능할 수 있도록 가능할까요?" (고객 상세 화면 스크린샷)

### 이전 상태
- 고객 생성·수정만 있고 **삭제 기능 전무** (`removeCustomer`/`dbDeleteCustomer` 부재). 잘못 등록한 고객/테스트 고객을 지울 방법이 없었음.

### DB FK 분석 (라이브 스키마)
`customers`를 참조하는 FK:
- `consultation_records.customer_id` → **NOT NULL + NO ACTION** (시술/매출 기록)
- `booking_requests.customer_id` → nullable + NO ACTION (예약)
- `portfolio_photos.customer_id` → nullable + **CASCADE** (포트폴리오)
- `customer_tags`·`small_talk_notes`·`membership_transactions` → CASCADE (고객 전용)

→ 시술 기록은 customer_id가 NOT NULL이라 unlink(NULL) 불가 + 기록 자체도 `portfolio_photos.record_id`·`small_talk_notes.consultation_record_id`(둘 다 NO ACTION) 의존성이 있어 함께 지우기엔 파괴적. 포트폴리오는 CASCADE라 그냥 두면 고객 삭제 시 샵 작업 사진이 함께 소실.

### 수정
1. **`dbDeleteCustomer(customerId, shopId)`** (db.ts):
   - 시술 기록 수 확인 → **1건이라도 있으면 차단** (`{ success:false, reason:'has_records', recordCount }`). 매출 정합성 보호 + 기록 NO ACTION 의존성 회피.
   - 기록 없으면: `booking_requests`·`portfolio_photos`의 customer_id를 **NULL로 unlink**(예약 일정·샵 포트폴리오 보존) 후 고객 삭제. 태그·메모·회원권거래는 CASCADE.
2. **`removeCustomer(id)`** (customer-store): DB 삭제 성공 시에만 로컬 제거(차단/실패 시 카드 유지). reason/recordCount 패스스루.
3. **고객 상세 페이지**(`customers/[id]`): 하단 "이 고객 삭제" 버튼(error 톤, 44px) + confirm 모달.
   - `customerRecords.length>0`이면 모달에서 "시술 기록 N건 있어 삭제 불가 — 먼저 삭제하세요" + [시술 기록 보기] 안내(삭제 버튼 미노출).
   - 없으면 일반 confirm → 삭제 후 `router.replace('/customers')`(뒤로가기 재진입 방지).

### 검증
- **라이브 DB 시뮬레이션**(트랜잭션 테스트, 잔여물 0 정리): 기록 없는 고객 → unlink+delete 정상, 태그 CASCADE 삭제, 포트폴리오 unlink 보존 확인. 기록 있는 고객 → NOT NULL 위반으로 unlink 불가 재현 → 차단 설계 근거 확보.
- RLS: 4개 테이블 모두 `*_shop_isolation`(cmd=ALL)로 원장 UPDATE/DELETE 가능 확인.
- tsc EXIT 0 / lint 0 error / build EXIT 0(37라우트).

## 8차 — 기본 커스텀 파츠 fallback (설정 미설정 샵도 고객에게 파츠 노출)

> 사용자 질문: "기본적으로 설정되어 있는 파츠들 있지 않아? 잘 보이고 선택도 되는거?" → 라이브 QA 중 발견: 설정을 한 번도 안 연 샵은 DB `settings.customParts`가 null이라 고객 화면에 파츠가 안 보임(네일숲 shop-001 등).

### 원인
- 기본 파츠 8종은 `partsStore`(localStorage)에만 있고, `CustomPartsManager`(설정 페이지) 마운트 시에야 DB로 동기화됨. → 원장이 설정을 한 번도 안 열면 DB customParts가 미설정(키 없음) → 사전상담 `shopData.customParts`·현장 `shopSettings.customParts`가 비어 파츠 섹션 미노출.
- 라이브 DB 확인: 네일숲(shop-001)은 `customParts` 키 자체가 없음(null), 나머지 샵은 8종 보유, 의도적 빈 배열(`[]`)인 샵은 없음.

### 수정
- **SSOT 신설** `src/data/default-parts.ts` — `DEFAULT_CUSTOM_PARTS`(큐빅·스와로브스키·진주·글리터·쉘·호일·스티커·참 8종, `CustomPartSetting[]`).
- `parts-store.ts` — 로컬 기본값 상수 제거하고 SSOT import.
- `db.ts fetchShopPublicData` — `customParts: settings.customParts ?? DEFAULT_CUSTOM_PARTS` (사전상담 fallback).
- `app-store DEFAULT_SHOP_SETTINGS.customParts` — `[...DEFAULT_CUSTOM_PARTS]` (현장모드·설정 fallback).
- **`?? ` 사용**으로 null/미설정만 기본값 대체, 원장이 의도적으로 전부 삭제한 `[]`는 존중. DB 백필 불필요(런타임 fallback이 네일숲까지 자동 정상화).

### 검증
- tsc/lint/build EXIT 0. 배포 후 네일숲 사전상담 파츠 노출 라이브 확인 예정.
